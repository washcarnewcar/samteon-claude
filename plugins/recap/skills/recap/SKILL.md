# recap — 작업 회고 정리

작업을 끝낸 뒤, 무엇이 어떻게 바뀌었는지 회고를 **채팅에만** 출력합니다.
파일로 저장하거나 커밋하지 않습니다.

## 1. 컨텍스트 수집

- 이번 대화에서 Edit/Write 한 파일과 그 변경의 "이전 모습"을 떠올립니다.
- before/after 근거를 코드로 확인합니다: `git diff`(unstaged), `git diff --staged`,
  필요하면 `git diff HEAD`. 세션 도중 외부 git GUI·stash 로 변경이 흩어졌을 수 있으니
  **현재 working tree 기준**으로 확인합니다.
- 인자(`$ARGUMENTS` / args)가 주어지면 그 주제·파일 범위로 한정하고, 없으면 이번 작업 전체를 대상으로 합니다.
- diff 가 비어 있거나 작업 범위가 불명확하면 **추측하지 말고** 사용자에게 무엇을 회고할지 한 번 확인합니다.

## 2. 출력 형식

아래 5단을 **한국어 존댓말**·마크다운으로 채팅에 출력합니다.
한자 금지. 프로젝트에 호칭 규칙이 있으면 준수합니다.

```
## <한 줄 제목 — 무엇을 한 작업인지>

### 이전 구조
- 바꾸기 전 어떻게 구성돼 있었는지 (어떤 파일/함수/흐름이 무슨 역할이었는지)

### 문제
- 그 구조에서 무엇이 문제였는지 / 왜 바꿔야 했는지

### 수정
- 어떻게 고쳤는지 — 핵심 변경을 동작 관점으로

### 영향받은 파일
- `path/to/file.kt:123` — 무엇을 바꿨는지 한 줄

### 검증
- 테스트/통합테스트/preview 등 어떻게 확인했는지. 안 했으면 "미검증"으로 솔직히 표기.
```

## 규칙

- **채팅 출력만.** 파일 생성·수정·커밋 금지.
- 추측으로 채우지 말 것 — diff·대화 근거가 있는 내용만 적고, 모르면 비워두거나 사용자에게 확인.
- "영향받은 파일"의 줄 번호는 현재 파일 기준 실제 위치로.
- 과장 금지 — 검증하지 않은 건 "미검증"으로 표기.
